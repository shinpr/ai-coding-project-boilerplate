# クイックスタート

新規または既存のTypeScriptプロジェクトに導入し、最初の`/implement`を実行するまでの手順です。

## プロジェクトを作成・更新する

新規プロジェクトの場合:

```bash
npx create-ai-project my-project --lang=ja
cd my-project
npm install
```

既存プロジェクトの場合は、プロジェクトルートで更新処理を実行します。

```bash
npx create-ai-project update --dry-run
npx create-ai-project update
```

更新処理は、管理対象のClaudeコマンド、エージェント、スキル、ルールを更新します。ソースコードとパッケージ設定は置き換えません。

## プロジェクトの前提情報を記録する

プロジェクト内でClaude Codeを起動します。

```bash
claude
```

続けて次のコマンドを実行します。

```text
/project-inject
```

ヒアリングでは、エージェントの判断を変えるリポジトリ固有の情報だけを記録します。

- プロジェクトの目的とドメイン制約
- 実装の合否を決めるリポジトリ固有の品質基準
- リポジトリの標準と異なるディレクトリ規約
- 現在の開発フェーズ
- スキーマ、API契約、インフラ設定など外部エビデンスの参照方法

結果は`.claude/skills/project-context/SKILL.md`に保存され、以降のセッションで読み込まれます。これらの前提が変わった場合は`/project-inject`を再実行してください。

## 変更を実装する

```text
/implement APIにレート制限を追加
```

ワークフローは次の順で進みます。

1. 成果、要件、除外事項、判断負荷を確認する。
2. 実装方針を決める前にリポジトリを調査する。
3. 小さな成果に明白な実装経路が1つある場合は、ドキュメントを作らず直接実装する。
4. 中・大規模では必要なDesign Docと作業計画書を作成して承認を得る。PRD、UI Spec、ADRは、それぞれが担う判断を必要とする場合だけ追加する。
5. 承認済みのタスク境界ごとに実装し、該当するリポジトリのチェックを実行してコミットする。
6. 中・大規模ではDesign Docに対して実装後検証を行い、実行できなかったチェックがあれば明記する。

プロダクト上の判断、長期的に残す成果物の承認、ユーザーだけが持つ権限、不可逆な操作が必要な場合は、ワークフローがユーザーに確認します。リポジトリ内で完結する可逆的な実装判断はエージェントが行います。

## 計画済みの作業を再開する

一貫したフローを再開する場合は`/implement`、承認済みの作業計画書または生成済みのタスクファイルがある場合は`/build`を使います。

```text
/implement 現在の実装を続きから完了して
/build docs/plans/20260809-feature-example.md
```

`/build`は選択した計画のタスクファイルを解決し、1つずつ完了させます。処理したタスクファイルは削除し、作業計画書は保持します。
