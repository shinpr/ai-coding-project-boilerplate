**命令上下文**：技能文件编辑后的维护工作流

## 核心目的

不只是维护一致性，而是提升 rule-advisor 的选择准确度。将元数据优化作为技能编辑工作流的收尾步骤。

## 执行流程

按顺序完成步骤 1-4。仅当当前步骤所述的证据或批准条件被满足时才推进。在每一条适用的完成标准都被满足后完成。

### 步骤 1：扫描技能文件

- Glob：`.claude/skills/*/SKILL.md`，获取所有技能文件
- Read：`.claude/skills/task-analyzer/references/skills-index.yaml`

### 步骤 2：同步并优化元数据

对每个技能验证以下内容：

| 元数据 | 验证内容 |
|----------|-------------|
| sections | 与 SKILL.md 中的 `## ` 章节 100% 一致 |
| tags | 准确反映文件内容的关键词 |
| typical-use | 明确指出具体的使用场景 |
| key-references | 覆盖当前的方法 |

### 步骤 3：变更必要性评估

**评估顺序**：
- 若 sections 已达到 100% 同步，则输出“同步已确认，无需更新。”并终止执行
- 若内容与标签的对应不存在任何不匹配，则设置 `no_changes_needed = true` 并终止执行
- 当且仅当存在可度量的改进时，才生成具体的修改提案，并给出精确的变更前后取值

**注意**：你不得强行做出变更。当未检测到改进时，你应报告“无需修改”并停止执行。

### 步骤 4：用户批准与应用

向用户提交提案，并在获得批准后应用：

```
[1/N] typescript-rules
  sections: 已同步
  tags 提案: +[functional-programming]
  typical-use: "旧描述" → "新描述"
```

## 完成标准

- [ ] 已扫描所有技能文件
- [ ] 已验证与 skills-index.yaml 的一致性
- [ ] 已评估变更必要性（若无需变更，已报告并终止）
- [ ] 若存在变更，已获得用户批准
- [ ] 已应用变更

## 错误处理

| 错误 | 动作 |
|-------|--------|
| 未找到 skills-index.yaml | 核对路径，若仍未找到则报告并终止 |
| SKILL.md 解析错误 | 跳过受影响的技能，继续处理其他技能 |
| 检测到大量不一致 | 提议从优先级最高者开始分阶段处理 |

## 执行时机

- 技能文件编辑后（必须）
- 新增技能文件时
- 技能大幅修订后
- 当发现 rule-advisor 的选择准确度下降时

**范围**：技能编辑工作后的元数据同步与 rule-advisor 精度优化。
