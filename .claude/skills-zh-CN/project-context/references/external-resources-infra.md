# 基础设施外部资源轴

用于部署、环境配置或基础设施即代码（infrastructure-as-code）工作的询问轴。

## 轴 1：IaC 来源

基础设施定义的权威来源。

**AskUserQuestion 选项**：
- 仓库中的 Terraform 配置
- 仓库中的 Pulumi 或 CDK 代码
- 仓库中的 Kubernetes manifests / Helm charts
- 云厂商原生模板（如 CloudFormation、Bicep、Deployment Manager）
- 手动控制台配置（无 IaC）
- 不适用

**后续问题（当该轴存在时）**：采集两个字段：
- **位置**：目录路径。
- **访问方式**：当 plan/apply 自动运行时的 CI 流水线名称，或操作员手动运行时的 CLI 命令。

## 轴 2：环境配置

各环境（开发、预发布、生产）之间的配置差异方式。

**AskUserQuestion 选项**：
- 仓库中的按环境划分的配置文件（如 `terraform/envs/`、`config/staging.yaml`）
- 由部署平台管理的环境变量
- IaC 工具自身的 Workspace 或 Stack 抽象
- 单一共享配置（无按环境差异）
- 不适用

**后续问题（当该轴存在时）**：采集两个字段：
- **位置**：存储环境特定值的配置文件路径、平台设置名称或 workspace 标识符。
- **访问方式**：文件读取、平台控制台 URL 或 CLI 命令。

当多个环境（开发、预发布、生产）被分别追踪时，按照 `template.md` 中的多实例规则，将每个环境作为独立条目采集，并以环境名称作为区分后缀。

## 轴 3：基础设施中的密钥

基础设施代码如何引用密钥，同时使其取值不进入源代码管理。

**AskUserQuestion 选项**：
- 通过 IaC 数据查找从密钥管理器获取的密钥
- 在 apply 时通过环境变量注入的密钥
- 与 IaC 一起提交的加密密钥文件
- 基础设施中无密钥
- 不适用

**后续问题（当该轴存在时）**：采集两个字段：
- **位置**：密钥管理器服务名称或 IaC 数据源标识符。
- **访问方式**：数据查找语法、环境变量名称，或 apply 时的注入机制。

当同一密钥存储也出现在后端（Backend）领域时，将此轴渲染为指回该位置的跨轴引用（记法定义于 `template.md`）。

## 轴 4：部署触发方式

基础设施和应用变更如何触达各环境。

**AskUserQuestion 选项**：
- 合并到特定分支时触发的 CI 流水线
- CI 中的手动审批步骤
- 操作员本地执行 apply
- 部署平台的推送自动部署
- 不适用

**后续问题（当该轴存在时）**：采集两个字段：
- **位置**：CI 流水线名称或部署平台标识符。
- **访问方式**：触发各环境的分支 / 标签约定，以及所需的任何手动审批步骤。

## 自我声明阶段

完成四个结构化轴后，追问一次：“除结构化问题已覆盖的内容外，本项目是否还依赖其他基础设施外部资源？请在下一条消息中逐一列出，或回复‘无’。”

将自由格式的回答记录在“基础设施”领域块的“其他资源”子章节下。即使所有结构化轴都返回“不适用”，也要执行此阶段。

仅通过自我声明才会浮现的资源示例：IaC 工具的状态存储后端、事件响应的运行手册文档、值班轮换、可观测性仪表盘、成本监控工具、合规 / 审计日志目标。
