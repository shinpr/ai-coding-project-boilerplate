# 前端外部资源轴

面向前端工作（组件实现、界面设计、视觉调整、设计系统迁移）的询问轴。

## 轴 1：设计来源

视觉规范的权威来源。

**AskUserQuestion 选项**：
- 设计工具（托管的设计平台）
- 仓库内的规范文件（如 `DESIGN.md`、`docs/design/...`）
- 公开文档 URL
- 仅有现有实现（没有独立的设计来源）
- 不适用

**后续问题（当该轴存在时）**：采集两个字段（“来源类型”由上述选项决定）：
- **位置**：公开 URL、仓库文件路径，或 MCP 目标标识符。
- **访问方式**：WebFetch、文件读取、MCP 服务器名称，或手动截图流程。

## 轴 2：设计系统

可复用的组件库与设计令牌（design tokens）。

**AskUserQuestion 选项**：
- 具备 MCP 服务器访问能力的组件库
- 带文档 URL 的组件库
- Storybook 或同类组件目录
- 仅有团队内部文档的内部包
- 无设计系统（临时组件）
- 不适用

**后续问题（当该轴存在时）**：采集两个字段：
- **位置**：Storybook URL、包名，或内部文档路径。
- **访问方式**：WebFetch、文件读取，或 MCP 服务器名称。

## 轴 3：指南

关于 UI 工作的使用指导、无障碍规则、反模式、命名约定。

**AskUserQuestion 选项**：
- 项目级指南文件（如 `DESIGN.md`、`docs/guidelines/...`）
- 外部文档站点
- 设计系统目录内嵌的指导内容
- 无文档化的指南
- 不适用

**后续问题（当该轴存在时）**：采集两个字段：
- **位置**：文件路径或 URL。
- **访问方式**：文件读取或 WebFetch。

当多个文件分别覆盖不同关注点（CSS、无障碍、i18n）时，按照 `template.md` 中的多实例规则，将每个文件采集为单独的条目。

## 轴 4：视觉验证环境

在实现过程中如何确认渲染输出。

**AskUserQuestion 选项**：
- 具备截图能力的端到端测试运行器
- Storybook 或同类隔离组件预览
- 浏览器自动化工具（专用 CLI 或 MCP 服务器）
- 仅手动浏览器检查
- 不适用

**后续问题（当该轴存在时）**：采集两个字段：
- **位置**：预览 URL、MCP 目标，或测试运行器标识符。
- **访问方式**：入口命令、MCP 服务器名称，或浏览器自动化工具名称。

## 自我声明阶段

在四个结构化轴之后，统一提问一次：“除了结构化问题已覆盖的内容之外，本项目还依赖其他前端外部资源吗？请在下一条消息中逐一列出，或回复‘无’。”

将自由格式的回答记录在“前端”领域块的“其他资源”子章节下。即使每个结构化轴都返回“不适用”，也要执行此阶段。

仅通过自我声明才会浮现的资源示例：品牌素材 CDN、字体托管服务、图标库订阅、控制视觉变体投放的 A/B 测试仪表盘、用于查看视觉 KPI 的分析仪表盘。
