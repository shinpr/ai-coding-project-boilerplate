# 技能评审标准

用于评估现有或已生成的技能内容质量的标准。

## 评审流程

### 步骤 1：模式扫描

1. 扫描 BP-001 至 BP-009。
2. 为每个未解决的问题记录一个稳定的发现 ID、规则 ID、严重程度、位置、原始文本、可观测影响以及建议修复方案。
3. 评估全部 10 条编辑原则。
4. 统计行数并估算规模类别。

在重新评审时，保留同一问题的 ID。按发现 ID 关联先前的解决情况。当提出的修改扩大了范围、重复了已有证明、或没有可观测影响时，将其记录为有依据的拒绝（`acceptedDeclines`）。有依据的拒绝对发现项、评级计数、未通过的原则以及必需的操作项均贡献为零。只有当新证据表明结果仍然不正确或无法验证时，才再次提出该问题。调用方需在重新评审之前解决每个 `user_decision`。

**分析检查点**：当 9 种模式均已覆盖、每个未解决的问题均有证据和稳定 ID、需保留的要求已明确说明、且没有未知因素妨碍如实评审时，方可继续。

### 步骤 2：渐进式披露评估

| 层级 | 目标 | 验证方式 |
|------|--------|-------------|
| Tier 1 | description | 通过 `creation-guide.md` 中的 description 质量检查清单 |
| Tier 2 | SKILL.md 正文 | 不超过 500 行，目标为 250 行；通过首屏测试、标准章节顺序及条件性防护检查；当正文超过 250 行目标时，保留的每个章节都须通过必要性测试 |
| Tier 3 | 引用文件/脚本 | 先压缩后拆分；引用文件包含必要的条件性细节，保持单层深度，且不存在嵌套的引用链 |

每个未通过的层级至少引用一条已有的 BP 或原则发现项。当 description 缺乏激活该技能所需的、针对其目标请求的选用依据时，Tier 1 判定为未通过；该失败会强制评级为 C。将激活范围或调用触发条件缺失或错误映射到 principle-9，将缺乏非基线区分价值映射到 principle-1。Tier 2 与 Tier 3 对评级没有独立影响，仅通过其所引用的发现项、原则结果或平衡性检查产生作用。仅在其他检查清单偏差具有可观测的选用影响时才予以记录。

对于纯技能（pure skills），需验证其可独立执行。当各副本均属必需时，跨独立加载的纯技能之间的重复内容是合理的；仅记录语义冲突或技能内部的重复。跨技能引用在编排和技能选用场景中是合理的。

### 步骤 3：评估与评级

1. 将未解决的问题保留在 `findings` 中，将有依据的拒绝保留在 `acceptedDeclines` 中。
2. 统计 P1 与 P2 发现项数量。
3. 仅统计状态为 `pass` 的原则数量。
4. 使用上述独立执行规则检查跨技能重叠。
5. 评估以下各项：
   - 过度优化：过多约束或衍生义务；超过 250 行但未完成压缩的内容
   - 工作衍生：发现项或可能性被转化为缺乏支撑的产物、测试、检查点或决策
   - 专业知识流失：重构过程中删除了领域知识
   - 清晰度权衡取舍：结构使要点变得晦涩
   - description 质量：frontmatter 中的 description 是否遵循触发指引
6. 给出评级。

**输出**：一份质量报告，包含：
- BP-001 至 BP-009 的覆盖情况
- 未解决的 `findings` 以及带依据的 `acceptedDeclines`
- 需保留的要求与未解决的输入项
- 渐进式披露与 10 条原则的评估结果
- 六项平衡性检查：意图保留、决策充分性、信息密度、约束必要性、工作量相称性、可追溯性
- 最终评级

**平衡性检查点**：每项平衡性检查须记录为通过或被阻断（附证据）。被阻断的检查项须引用某一发现项，且会阻止评级为 A。

## 评级标准

| 评级 | 标准 | 建议 |
|-------|----------|----------------|
| A | 0 个 P1、0 个 P2 发现项，9 条以上原则通过，Tier 1 通过 | 可投入使用 |
| B | 0 个 P1、至多 2 个 P2 发现项，7 条以上原则通过，Tier 1 通过 | 可接受，附带改进建议 |
| C | 存在任何 P1、超过 2 个 P2 发现项、通过原则数少于 7 条，或 Tier 1 未通过 | 需要修订 |

## 评审模式差异

| 方面 | 创建 | 修改 |
|--------|----------|-------------|
| 范围 | 全部内容，全面评审 | 变更部分加回归检查 |
| BP 扫描 | 全部 9 种模式 | 与变更相关的模式 |
| 跨技能检查 | 全面重叠扫描 | 验证变更未引入冲突或不必要的重复 |
| 额外检查 | — | 单独报告变更范围之外的问题 |
