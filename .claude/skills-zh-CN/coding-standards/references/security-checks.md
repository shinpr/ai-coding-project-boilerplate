# 安全检查模式

最后审阅时间：2026-09-23

## 稳定模式

这些模式可以通过直接搜索源代码发现，其形态不随生态系统的变化而改变。

### 硬编码密钥
- 在源代码中以字符串字面量形式赋值的凭据、API 密钥或令牌
- 包含嵌入密码的连接字符串
- 存储在源文件中的私钥或证书
- 特定服务商的令牌格式，可通过前缀而非变量名识别

### SQL 字符串拼接
- 通过字符串拼接或与变量插值构造、而非使用参数化数据访问的 SQL 语句

### 动态代码与命令执行
- 非静态输入流入 `eval()`、`Function()`、`exec()` 或 `compile()`
- 使用变量路径进行动态 import 或 require
- 不可信的值流入 shell 命令字符串或其参数

### 不安全的反序列化
- 使用 `pickle.loads()`、未指定 SafeLoader 的 `yaml.load()` 或 `marshal.loads()` 反序列化不可信输入
- `JSON.parse()` 的输出被直接传入 `eval()` 或 `Function()`

### 不可信的资源目标
- 未经净化处理、由用户输入构造的文件系统路径，包括压缩包内的条目名称和符号链接目标
- 主机、端口或协议来自用户输入的出站请求，包括经重定向后到达的目标（服务端请求伪造）
- 两个方向上的共同点在于：调用方能够选定一个它无法直接访问的资源

### 明文或未经校验的传输
- 将凭据、令牌或个人数据发送到源代码中构造或配置的非 TLS 目标
- 在客户端、代理或传输配置中禁用了 TLS 证书或主机名校验

### 携带凭据的跨源暴露
- 允许攻击者可控的来源读取已认证的响应，典型情况是在启用 `Access-Control-Allow-Credentials` 的同时，不经允许列表检查就回显请求的 `Origin`
- 单独的通配符来源不属于此模式：浏览器会拒绝对携带凭据的请求使用 `*`，而对回显的来源进行允许列表校验才是正确的实现

## 趋势敏感模式

更新时间：2026-09-23
来源：OWASP Top 10:2025；DryRun Agentic Coding Security Report（2026-03）；Shai-Hulud npm 蠕虫攻击活动（2025-09 起）

### 对象级授权缺口（OWASP A01:2025）
- 调用链中没有身份验证或授权检查即可到达的路由处理程序和资源操作
- 验证了身份，却未验证调用方对请求中所指定资源是否拥有权限的处理程序
- 使用请求中的标识符选取记录，却未将查询限定在调用方所属的租户或所有权范围内
- 授权未覆盖集合中每个目标的批量、批处理、导出和导入操作
- 请求体中覆盖了权限检查所假定的资源、所有者、角色或范围的字段
- 针对变更后的攻击面，核查每一处可到达、且其授权行为可能改变安全结论的资源访问

### 异常情况处理不当（OWASP A10:2025）
- 在响应中暴露内部系统细节（堆栈跟踪、数据库错误、文件路径）的错误处理程序
- 在异常发生时授予访问权限、跳过身份验证或绕过授权的错误处理程序
- 安全关键操作（身份验证、授权、加密操作）缺少错误处理

### 依赖与流水线完整性（OWASP A03:2025）
- 新增的、会运行安装时脚本（`preinstall`、`postinstall` 或其他生态中的等效机制）的依赖项
- 在安装时解析版本、而非使用已提交锁文件的安装路径

当变更包含流水线定义时：
- 通过可变的标签或分支、而非不可变的修订引用的第三方流水线 action
- 向来自不可信 fork 的代码暴露仓库密钥或可写令牌的流水线触发器
- 将事件提供的值（标题、分支名、评论内容）直接插入流水线 shell 步骤
