# セキュリティチェックパターン

Last reviewed: 2026-09-23

## Stable Patterns

ソースを直接検索して見つけられ、エコシステムが変わっても形が変わらないパターン。

### ハードコードされたシークレット
- ソースコード内で文字列リテラルとして代入された認証情報、APIキー、トークン
- パスワードが埋め込まれた接続文字列
- ソースファイルに保存された秘密鍵や証明書
- 変数名ではなくプレフィックスで判別できる、プロバイダー固有のトークン形式

### SQL文字列結合
- パラメータ化されたデータアクセスではなく、文字列結合や変数の埋め込みで構築されたSQL文

### 動的なコード・コマンド実行
- 静的でない入力が到達する `eval()`、`Function()`、`exec()`、`compile()`
- 変数パスによる動的importやrequire
- 信頼できない値がシェルコマンド文字列やその引数に流れ込むパターン

### 安全でないデシリアライゼーション
- 信頼できない入力での`pickle.loads()`、SafeLoaderなしの`yaml.load()`、`marshal.loads()`
- `JSON.parse()`の結果を`eval()`や`Function()`へ直接渡すパターン

### 信頼できないリソース指定
- ユーザー提供入力からサニタイズなしで構築されたファイルシステムパス（アーカイブ内のエントリ名やシンボリックリンクの参照先を含む）
- 送信先のホスト、ポート、スキームがユーザー提供入力から決まる外部リクエスト（リダイレクト後に到達する送信先を含む。サーバーサイドリクエストフォージェリ）
- どちらの方向でも、呼び出し元が直接には到達できないリソースを選べてしまう

### 平文または未検証の通信
- ソース内で構築・設定された非TLSの送信先へ、認証情報、トークン、個人データを送るパターン
- クライアント、エージェント、通信設定でTLS証明書またはホスト名の検証が無効になっているパターン

### 認証情報付きのクロスオリジン露出
- 攻撃者が制御できるoriginに、認証済みレスポンスの読み取りを許すパターン。典型例は、`Access-Control-Allow-Credentials`を有効にしたまま、リクエストの`Origin`を許可リストで確認せずに反射するもの
- ワイルドカードoriginだけではこのパターンに当たらない。認証情報付きのリクエストではブラウザが`*`を拒否し、許可リストで検証したうえでoriginを反射するのは正しい実装である

## Trend-Sensitive Patterns

Updated: 2026-09-23
Sources: OWASP Top 10:2025; DryRun Agentic Coding Security Report (2026-03); Shai-Hulud npm worm campaigns (2025-09 onward)

### オブジェクト単位の認可の欠落（OWASP A01:2025）
- 呼び出しチェーン内に認証チェックも認可チェックもないまま到達できるルートハンドラやリソース操作
- 認証は確認するが、リクエストが指定した特定のリソースに対する呼び出し元の権利を確認しないハンドラ
- リクエストの識別子でレコードを選ぶ際に、呼び出し元のテナントや所有範囲でクエリを絞り込んでいないパターン
- 認可がセット内のすべての対象に及んでいない一括処理、バッチ、エクスポート、インポート
- 権限チェックが前提としたリソース、所有者、ロール、スコープを、リクエストボディのフィールドで上書きできるパターン
- 変更された攻撃対象面について、認可の振る舞いがセキュリティ上の結果を変えうる到達可能なリソースアクセスをそれぞれ検証する

### 例外条件の不適切な処理（OWASP A10:2025）
- レスポンスに内部システム詳細（スタックトレース、データベースエラー、ファイルパス）を露出するエラーハンドラ
- 例外発生時にアクセスを許可、認証をスキップ、または認可をバイパスするエラーハンドラ
- セキュリティ上重要な操作（認証、認可、暗号操作）でのエラーハンドリング欠如

### 依存関係とパイプラインの完全性（OWASP A03:2025）
- インストール時スクリプト（`preinstall`、`postinstall`、またはエコシステムでの相当機能）を実行する新規の依存関係
- コミット済みのロックファイルではなく、インストール時にバージョンを解決するインストール経路

変更にパイプライン定義が含まれる場合:
- 不変のリビジョンではなく、可変のタグやブランチで参照されたサードパーティのパイプラインアクション
- 信頼できないフォークのコードに、リポジトリのシークレットや書き込み可能なトークンを渡すパイプラインのトリガー
- イベントから渡される値（タイトル、ブランチ名、コメント本文）をパイプラインのシェルステップへ直接埋め込むパターン
