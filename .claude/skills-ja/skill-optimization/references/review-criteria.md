# スキルレビュー基準

既存または生成済みスキルコンテンツの品質評価基準。

## レビューフロー

### Step 1: パターン検出

1. BP-001〜BP-009を確認する。
2. 未解決の指摘ごとに、再レビューでも維持する指摘ID、ルールID、重大度、場所、原文、観測可能な影響、修正案を記録する。
3. 10の編集原則をすべて評価する。
4. 行数を集計し、サイズ区分を判定する。

再レビューでは同じ指摘のIDを維持し、以前の解決方法をfinding IDで対応付ける。提案された変更がスコープを増やす、証明を重複させる、または観測可能な影響を持たない場合は、根拠付きの却下を`acceptedDeclines`へ記録する。承認済みの却下は、指摘件数、グレード、原則の不合格、必須対応に算入しない。新しい根拠によって結果が依然として不正または検証不能だと示された場合に限り、同じ指摘を再掲する。`user_decision`は呼び出し元がユーザー回答を得てから再レビューする。

**分析ゲート**: 9パターンをすべて確認し、未解決の各指摘に根拠と維持可能なIDがあり、保持すべき要件が明示され、忠実なレビューを妨げる不明点がない場合に次へ進む。

### Step 2: Progressive Disclosure評価

| 階層 | 対象 | 検証項目 |
|------|------|----------|
| Tier 1 | description | `creation-guide.md`のdescription品質チェックリストに合格 |
| Tier 2 | SKILL.md本文 | 500行以下、目標250行。最初の画面、標準セクション順序、条件付きガードを満たし、目標超過時は各セクションが必要性テストに合格 |
| Tier 3 | 参照・スクリプト | 圧縮を分割より先に行い、referenceは必要な条件付き詳細だけを含み、1階層下に置き、参照の連鎖を作らない |

failとなる各Tierは、既存のBPまたは編集原則に基づく指摘を1件以上参照する。意図した依頼でスキルを起動するための選択根拠がdescriptionにない場合はTier 1をfailとし、グレードCとする。起動範囲または呼び出し側のトリガーが欠落・不正な場合はprinciple-9、ベースライン外の識別材料がない場合はprinciple-1へ対応付ける。Tier 2とTier 3は単独ではグレードを変えず、参照先の指摘、原則評価、またはバランス確認を通じて反映する。その他のチェックリスト違反は、スキル選択への観測可能な影響がある場合だけ指摘する。

pure skillは単独実行できるかを確認する。独立して読み込まれるpure skill間の重複は、各スキルに必要な場合は有効とし、意味上の競合またはスキル内重複だけを指摘する。スキル間参照はorchestrationまたはskill selectionを担う場合に有効とする。

### Step 3: 評価とグレード判定

1. 未解決の問題を`findings`、根拠付きで却下した指摘を`acceptedDeclines`に保持する。
2. P1とP2の指摘件数を集計する。
3. `pass`の原則だけを合格数に算入する。
4. 上記の単独実行規則に従ってスキル間の重複を確認する。
5. 次を評価する。
   - 過剰最適化: 過剰な制約または作業義務。圧縮を完了せずに250行を超える内容
   - 作業生成: 指摘や可能性が、根拠のない成果物、テスト、ゲート、判断を生む
   - 知識の欠落: 構造化によってドメイン知識が失われる
   - 可読性低下: 構造化によって要点が不明瞭になる
   - description品質: frontmatterのdescriptionがトリガー指針に準拠する
6. グレードを判定する。

**出力**: 次を含む品質レポート:
- BP-001〜BP-009の網羅結果
- 未解決の`findings`と根拠付きの`acceptedDeclines`
- 保持すべき要件と未解決の入力
- Progressive Disclosureと10原則の結果
- 意図の保持、判断に必要な情報、情報密度、制約の必要性、作業量の妥当性、追跡可能性の6つのバランス確認
- 最終グレード

**バランスゲート**: 各確認項目に根拠付きでpassまたはblockedを記録する。blockedは指摘を参照し、グレードAを許可しない。

## グレード判定基準

| グレード | 基準 | 判定 |
|----------|------|------|
| A | P1指摘0件、P2指摘0件、9原則以上pass、Tier 1 pass | 即使用可 |
| B | P1指摘0件、P2指摘2件以下、7原則以上pass、Tier 1 pass | 改善点を認識した上で使用可 |
| C | P1指摘あり、P2指摘3件以上、passが7原則未満、またはTier 1 fail | 修正が必要 |

## レビューモード別の差異

| 観点 | creation | modification |
|------|----------|-------------|
| 対象範囲 | 全コンテンツを網羅的に確認 | 変更箇所と退行を確認 |
| BPスキャン | 全9パターン | 変更に関連するパターン |
| スキル間確認 | 全体の重複スキャン | 変更による競合または不要な重複がないか確認 |
| 追加確認 | — | 変更スコープ外の問題は別途報告 |
