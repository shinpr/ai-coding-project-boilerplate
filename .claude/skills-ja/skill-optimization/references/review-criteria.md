# スキルレビュー基準

既存または生成済みスキルコンテンツの品質評価基準。

## レビューフロー

### Step 1: パターン検出

**入力**: スキルコンテンツ（SKILL.md frontmatter + 本文）

**手順**:
1. BPパターン（BP-001〜BP-008）を順に検出
2. 記録: パターンID、重大度、該当箇所、原文
3. 9つの編集原則に照らして評価
4. 総行数を集計しサイズ区分を判定

**出力**: 重大度・該当箇所・原文を含む検出リスト。

**分析ゲート**: BP-001〜BP-008をすべて確認し、各問題に一意な指摘IDと引用した根拠があり、保持すべき要件が明示され、忠実なレビューを妨げる未解決の入力がない場合にのみ次へ進む。

### Step 2: Progressive Disclosure評価

3階層の開示アーキテクチャを検証:

| 階層 | 対象 | 検証項目 |
|------|------|----------|
| Tier 1 | description | description品質チェックリスト（creation-guide.md参照）に合格するか |
| Tier 2 | SKILL.md本文 | 500行以下（理想250行）、最初の30行で概要把握可能、標準セクション順序、条件付きセクションにIF/WHENガード |
| Tier 3 | 参照・スクリプト | SKILL.mdから1階層のみ、400行超のSKILL.mdは分割必須 |

pure skillは単独実行できるかを確認する。独立して読み込まれるpure skill間の重複は、各スキルに必要な場合は有効とし、意味上の競合またはスキル内重複だけを指摘する。スキル間参照はorchestrationまたはskill selectionを担う場合に有効とする。

### Step 3: 評価とグレード判定

**入力**: 検出リスト + スキルコンテンツ

**手順**:
1. P1・P2問題の件数を集計
2. 原則の合否を集計（合格/部分的/不合格）
3. スキル間の重複を確認
4. **バランス評価**:
   - 過剰最適化: 単純なトピックに対して制約過多
   - 知識の欠落: 構造化でドメイン固有の知見が消失
   - 可読性低下: 構造化で要点が不明瞭
   - 制約の必要性: スキル内の各制約が、明示された要件または検出結果に遡れること。明示された要件を担保しないまま有効な解を除外している制約は指摘する
   - description品質: frontmatterのdescriptionが指針に準拠
5. グレード判定

**出力**: 以下を含む品質レポート：
- BP-001〜BP-008の網羅結果
- ID、重大度、場所、引用した根拠を含む指摘
- 指摘ごとに1つの適用または見送りの解決方法と理由
- 保持すべき要件と未解決の入力
- Progressive Disclosureと9原則の結果
- 評価と優先順に並べたアクション項目

**最適化ゲート**: 各指摘に解決方法がちょうど1つあり、すべての変更提案を指摘またはプロジェクト情報源まで追跡でき、保持すべき要件がすべて残っていること。

**バランスゲート**: 意図の保持、判断に必要な情報、情報密度、制約の必要性、追跡可能性をすべて満たす。不明な根拠によって確認できない場合は作業を止め、必要な根拠または判断を具体的に示す。

## グレード判定基準

| グレード | 基準 | 判定 |
|----------|------|------|
| A | P1問題0件、P2問題0件、原則8つ以上合格、Tier 1合格 | 即使用可 |
| B | P1問題0件、P2問題2件以下、原則6つ以上合格、Tier 1合格 | 改善点を認識した上で使用可 |
| C | P1問題あり、またはP2問題3件以上、または原則合格6未満、またはTier 1不合格 | 修正が必要 |

## レビューモード別の差異

| 観点 | creation | modification |
|------|----------|-------------|
| 対象範囲 | 全コンテンツを網羅的に | 変更箇所 + 退行チェック |
| BPスキャン | 全8パターン | 変更に関連するパターンに注力 |
| スキル間確認 | 全体の重複スキャン | 変更で重複が発生していないか |
| 追加確認 | — | 変更スコープ外の問題は別途報告 |
