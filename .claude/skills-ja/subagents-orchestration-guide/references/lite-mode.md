# Liteモード

Liteモードは、確認済みの成果、ユーザー承認の停止点、権限境界、実装チェック、完了のエビデンスを維持しながら、中間の検証呼び出しを減らす。解決したモードに従って、レシピの呼び出しとその結果ゲートを適用する。

## 呼び出し集合

| 呼び出し | Liteモードでの振る舞い |
|---|---|
| code-verifier | 省略する。この呼び出しによる`verification_evidence`や`prior_layer_verification`は下流に渡さない。 |
| design-sync | 省略する。後続の承認停止点は、直前の省略されないステップの後に置く。 |
| security-reviewer | 実装後レビューの集合から省略する。code-reviewerは引き続き実行する。 |
| 作業計画書のタスク集合に対するタスクごとのquality-fixer | 以下の最終品質チェックに置き換える。executorの結果と必要な統合/E2Eレビューを受理した後、レシピの既存コミットポイントで完了済みタスクをコミットする。 |

省略した呼び出しには、解釈・照合・パスとして報告する結果がない。報告では、該当する検証をLiteモードで省略したと明記する。ユーザーが指定した専門レビューは、既定の呼び出し集合にかかわらず、依頼された成果として実行する。

Smallとその他の単一サイクルのフローでは、quality-fixerがすでに最終実行に当たるため、その呼び出しを維持する。レビュー修正の品質チェックと、必要な統合/E2Eテストレビューも引き続き適用する。

## 最終品質チェック

最後のタスクのコミット後、実装後レビューの前に、完了済みタスクがある各レイヤーで、該当するquality-fixerを1回呼び出す。既存の入力を渡す:

- `direct_scope`: 作業計画書の成果と対象外、そのレイヤーの完了済みタスクファイルのパスと変更した実装パス、それらの全タスクのOperation Verification Methods。このスコープにコミット済みタスクの変更を含める。
- `qualityCommand`: 呼び出し元、出典ソース、リポジトリ設定が指定している場合に、その正となる品質コマンド。

「専門エージェントの結果の受理」に従って結果を受理する。`stub_detected`の場合は、`incompleteImplementations`の各項目を変更せず、その項目を所有するタスクのexecutorへ戻す。実装結果と必要なテストレビューの結果を受理した後、最終品質チェックを繰り返す。

生じた修正は、該当する品質結果が得られた後、レシピの既存コミット境界でコミットする。保持した検証上の制約は、通常の完了手順に従って記録する。レビュー後の変更にも該当する品質チェックを適用し、後続の変更が無効化するまでは有効なエビデンスを再利用する。
